## 优化目标:网页首屏秒开(不再等 torch/funasr)

### 根因
- `web_ui.py:12` 顶层 `from bili_core import (...)` 同步拉起 `import funasr`(torch 全家桶,约 10-30 秒)+ modelscope + bilibili_api,全部阻塞在首屏渲染之前
- 首屏预热线程(`web_ui.py:76-77`)与首屏 import 并发抢 CPU/磁盘
- `api.py` 同样在 uvicorn 接受请求前 import bili_core
- 硬约束(AGENTS.md 陷阱 #1):funasr 必须先于 bilibili_api/modelscope 加载,否则 Windows 段错误。该顺序由 `bili_core.py:19-42` 内部代码保证,本方案不改变相对顺序,任何入口懒加载都是安全的。

### 改动一:bili_core.py — 非 funasr 的重 import 改为函数内懒加载
1. 保留 `import funasr`(`bili_core.py:19-23`)顶层最先加载 —— 顺序约束的核心不动
2. `from bilibili_api import video, sync` + `select_client("httpx")`(行 32-39)→ 移入 `get_video_info`(唯一 bilibili_api 使用点,行 372-373;首次调用时 funasr 早已加载,顺序安全)
3. `from modelscope.hub.snapshot_download import snapshot_download`(行 40)→ 移入 `download_paraformer_model` / `download_vad_model` / `download_sensevoice_model` 三个函数内(使用点:198/225/259)
4. `from openai import OpenAI`(行 41)→ 移入 `summarize_content`(486)和 `summarize_content_stream`(520)函数内
5. 删除未使用的 `import requests`(行 25,全文无调用)
6. `load_dotenv`(行 42)保留顶层(dotenv 极轻,模块级配置依赖它)
- 效果:import bili_core 只剩 funasr+torch;后台预热和 api.py 启动都显著变快

### 改动二:web_ui.py — bili_core 懒加载 + 后台预热
1. 删除第 12-23 行顶层 `from bili_core import (...)`
2. 新增模块级 `_get_core()`(双检锁,首次调用时 `import bili_core` 并缓存)+ `_backend_ready` 标志(预热线程完成后置位)
3. 预热线程(模块级标志只起一次):`_get_core().preload_asr_model()`,完成后 `_backend_ready = True`;首屏不再调用任何 bili_core 函数
4. 侧边栏 `from bili_core import LLM_API_KEY`(407 行)→ 模块级 `load_dotenv` + `os.getenv("LLM_API_KEY")`
5. ASR 状态指示(474 行):`_backend_ready` 为 True 时走 `_get_core().get_asr_model_status()`,否则显示「正在后台预热中…」
6. 全部调用点改为 `_get_core().xxx`:extract_bvid_and_p(422)、load_cached_transcription(446)、get_video_info(601)、download_audio(623)、transcribe_audio(641)、save_transcription(651)、summarize_content_stream(685)、save_results(699)
7. 附带修复:`monitor_sessions` 的启动守卫从 `st.session_state['monitor_started']`(per-session,每个 tab 起一个线程)改为模块级标志(行 62-65)

### 改动三:api.py — 不改
改动一后 `import bili_core` 自动变轻,api.py 启动自动受益;避免扩大改动面。

### 验证(无测试框架,真机手动回归)
1. 修改前后对比:启动到页面可交互的时间(首屏应从几十秒降到几秒)
2. 首屏后侧边栏显示「语音识别引擎正在后台预热中…」,后台完成后变为就绪/待命
3. 完整流程回归(段错误敏感场景,必须真机):输入 B 站链接 → 获取视频信息(bilibili_api 懒加载)→ 下载 → 转录(funasr 路径)→ AI 总结(openai 路径),确认三个懒加载点正常
4. 有转录缓存时:缓存命中 → 跳过前三步 → 直接总结路径
5. `uvicorn api:app` 冒烟:启动时间明显缩短
6. 多 tab 打开只起一个 monitor 线程

### 风险
- 段错误顺序约束:funasr 仍顶层最先,相对顺序不变;靠真机完整转写回归兜底
- 懒加载引入 NameError:调用点已全部列全,逐一核对
- 行为变化:首屏显示时模型未就绪,若用户立即点「开始处理」,主线程会在 import 锁上等待后台完成(与现在"转圈等待"体验一致)
