## 实现目标

当用户提交的 BV 号（+分集号 p）**以前已经处理过**时，跳过前三个步骤（获取视频信息 / 下载音频 / 音频转录），直接用已有的转录稿重新进行 AI 总结。

基于你的选择，方案如下：① 不迁移旧文件（旧标题命名文件无法被复用），只有今后新处理的视频按 BV 号命名；② 命中缓存时直接跳转并在界面提示；③ 转写完成即缓存（即使总结失败，下次也能跳过前三步）。

## 一、`bili_core.py` 改动

### 1. 新增缓存读写工具函数

参照 `bili_core_backup_sherpa.py:558-574` 的旧实现，用 BV 号作为缓存键，重新引入两个函数（放在 `save_results` 附近，约第 543 行前）：

- **`load_cached_transcription(bvid, p=1)`**
  - 读 `intermediate_files/{bvid}_p{p}_transcription.txt`
  - 解析文件内容（格式：`视频标题: ...\n视频链接: ...\n\n转录内容:\n\n{text}`），返回 `(title, text)`；文件不存在或解析失败返回 `(None, None)`
  - 标题优先从文件头部"视频标题:"行解析；若需展示视频卡片信息，标题就够用了（封面/UP 主等卡片非必需，命中缓存时不强制重新拉取）

- **`save_transcription(bvid, title, text, p=1)`**（从备份恢复，`bili_core_backup_sherpa.py:523-535`）
  - 写 `intermediate_files/{bvid}_p{p}_transcription.txt`，格式与现有 save_results 写的转录稿完全一致，保证 load_cached_transcription 能解析

### 2. 修改 `save_results(bvid, title, text, summary, p=1)` （第 543-564 行）

把转录稿和总结的文件名都从 `safe_title` 改为 **`{bvid}_p{p}`**：
- 转录稿：`intermediate_files/{bvid}_p{p}_transcription.txt`（同时复用上面新增的 `save_transcription`，避免重复代码）
- 总结：`final_outputs/{bvid}_p{p}_summary.md`
- 保留 `limit_directory_size` 清理逻辑
- 删除不再使用的 `safe_title` 变量（及其 `re.sub` 调用）

> 说明：转录稿文件已由新步骤在第 3 步落盘，这里 `save_results` 可改为仅写总结 md + 复用 `save_transcription`（幂等覆盖，保证最新），二者择一即可，实现时选简洁的"复用 save_transcription"。

## 二、`web_ui.py` 改动

### 3. 顶部导入新增函数（第 12-21 行）

把 `load_cached_transcription` 加入从 `bili_core` 的导入列表。

### 4. 点击"开始处理"时检测缓存（第 411-442 行的按钮逻辑）

在 `bvid/p` 校验通过后、进入全新处理流程前，插入缓存命中分支：

```
title, text = load_cached_transcription(bvid, p)
if text:   # 命中缓存
    _clear_transient_processing_state()
    st.session_state['url'] / ['bvid'] / ['p'] / ['task_key'] / ['active_task_key'] 赋值（同现有流程）
    st.session_state['title'] = title
    st.session_state['text'] = text
    st.session_state['cached_summary'] = True        # 激活原本的「已加载缓存」死代码逻辑
    st.session_state['cache_hit'] = True             # 新标志，用于步骤卡片展示「跳过前三步」提示
    st.session_state['step'] = 4                     # 直接进入第 4 步 AI 总结
    st.rerun()
# 未命中 → 走现有完整流程
```

保留现有 `same_completed_task`（同一会话内已完成任务的内存复用）逻辑不变。

### 5. 转写完成后立即落盘（第 605-619 行，step==3 分支）

在 `transcribe_audio` 成功、删除音频文件**之前或之后**，新增：
```
save_transcription(bvid, title, text, p)
```
确保即使第 4 步 AI 总结失败，下次提交同 BV 也能跳过前三步。
（`bvid/p/title` 此时都在 `st.session_state` 中；`text` 是刚转写出的结果）

### 6. 步骤卡片展示「跳过」状态（第 512-531 行）

当 `st.session_state.get('cache_hit')` 为真时，对前三个步骤卡片渲染为"已跳过"样式（如灰色 + `⏭️` 标记 + 文案"已复用缓存"），而非"已完成 ✅"。这样进度面板能清楚反映"前三步被跳过、直接进入 AI 总结"。

实现方式：在现有的 `current_step > step_num` / `== step_num` / else 三分支基础上，为前三步加一个 `cache_hit` 的特殊分支输出 `step-card step-skipped` 类（复用现有 CSS 类名风格，新增一个轻量样式即可）。

### 7. 命中提示横幅（第 552-556 行附近）

命中缓存后 `final_summary` 区已能通过现有 `cached_summary` 分支显示"🎉 已加载缓存的总结内容"提示（该死代码现在会被真正激活）。
另外在第 4 步流式总结开始时（第 625 行 step==4 分支），如果 `cache_hit`，先 `st.info("✨ 检测到该视频已处理过，已跳过下载与转录，正在重新生成总结…")` 提示用户。

## 三、改动范围与风险

**改动文件**：仅 `bili_core.py`、`web_ui.py` 两个文件，不引入新依赖。

**向后兼容**：
- 旧的标题命名文件不会被读取也不会被破坏（不迁移，符合你的选择）
- 新处理的视频统一用 `{bvid}_p{p}` 命名
- `save_results` 改名后，未来重新处理同一视频会**覆盖**同名（同 BV）的旧 BV 命名文件——这是期望行为（转录稿以最新为准）

**不变的行为**：内存级 `same_completed_task` 复用、音频下载后删除、30MB 缓存上限清理、ASR 模型预加载均不受影响。

**潜在边界**：
- 转录稿文件解析依赖固定的 `视频标题:` / `转录内容:` 标记格式——这正是现有 `save_results` 写入的格式，自洽
- 多分集（p>1）已通过 `{bvid}_p{p}` 键区分，无需额外处理

## 四、验证方式（实现后）

1. 提交一个**新**视频 → 走完整 4 步 → 检查 `intermediate_files/{bvid}_p{p}_transcription.txt` 和 `final_outputs/{bvid}_p{p}_summary.md` 是否生成
2. 同一 BV 再次提交 → 进度卡片前三步应显示"跳过"、出现"✨ 检测到该视频已处理过"提示、直接进入 AI 总结流式输出
3. 模拟总结失败（临时关掉 LLM_API_KEY）→ 检查转录稿仍已落盘 → 重新提交同 BV 仍能跳过前三步
4. 检查旧的标题命名文件未被读取/未报错
